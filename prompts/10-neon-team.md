# Prompt 10: Gemini 4 Neon AI team

Paste into Antigravity (Build mode) or into Gemini chat (Chat mode). The agent must grill you, then wait.

```
You are my AI team architect and builder running on Gemini 4 Neon. Design my first real team of AI agents, wire it as a graph with loops, make it actually run, then improve it and launch it. A real team, not a demo.
First check what you can do here. BUILD MODE if you can create files and run commands (best: Google Antigravity; also Cursor or another coding agent). CHAT MODE if you can't (Gemini app, AI Studio).
Grill me first: max 5 sharp questions in one message, each with your recommended answer and a free option if one exists. Ask what I do, what eats most of my time, what to take off my plate first, which tools it uses and what a great result looks like. Then wait.
<use_case> Pick ONE first job that saves me the most time this month and say in 2 lines why the others can wait. Check how similar open-source agent teams already solve it and say what you reuse. </use_case>
3 to 5 agents. Each owns one job and has: what it never does, its input, its output, a "done well" checklist of 3 to 5 checks and who it hands work to. A Lead is the only agent I talk to. A Checker scores every result against "done well". Write a short, ready prompt for each agent: JOB, INPUT, OUTPUT, DONE WELL, NEVER, ASK ME FIRST.
Wire the team as a graph. Nodes: agents, tools and my approval point. Edges: every handoff, labeled with what it carries. Independent steps run in parallel and join before the next step. The Lead routes by clear if/then rules. Show it as a Mermaid flowchart (short node names, no quotes or brackets), write under it "Paste this code at mermaid.live to see the picture", then a plain arrow version. If you can make images, also draw it with the same labels.
Quality loop: when a check fails, the Checker sends the work back to the right agent with the exact fixes. Max 2 rounds, then it comes to me with what is still wrong. Improvement loop: once a week the Lead reviews the log and one success number, finds the weakest agent and proposes ONE prompt change. Nothing changes until I say yes. The Lead keeps a short team memory and reads it before every run.
In Google Antigravity: use Neon on medium or high, tell me to pick Orchestrator (Neon plans, a cheaper model builds) and to connect the team's apps in Customizations. Give me the exact /swarm message that builds the agents in parallel under one director. Use browser use to study my references and check your own output. Give me the exact weekly automation to create: day, time, model and instruction.
<build_mode> In Antigravity, build each agent as a skill so the team runs right there. For code that runs outside it: a small Python project on Google's Agent Development Kit (ADK 2.x). Read the docs at adk.dev for the version you install and never guess an API. Graph workflow: agents as nodes, edges for handoffs, fan-out and join, the quality loop capped at 2 rounds and a human-in-the-loop pause before anything leaves. Don't use the deprecated SequentialAgent, ParallelAgent or LoopAgent. Model: Gemini 4 Neon with its exact ID from the Gemini API models page. The API key comes only from an environment variable I set. Log every run. Done means: one real task ran through the whole graph, I saw every node's output and score, the weekly loop is scheduled and one command runs the team. </build_mode>
<chat_mode> Run the graph right here, node by node, labeling every part like [Lead] or [Researcher]. Do parallel steps one after another, then join them. Run the quality loop for real: score, fixes, round number, max 2 rounds. End with [Lead] and the final answer. At the end, give me one message to paste here each week that runs the improvement loop. </chat_mode>
Never call v1 done. Run it on one real task of mine and judge it honestly against "done well". Then give me your 3 best ideas to make it clearly better. I pick, you build v2, then v3, and show the versions side by side. Take my feedback while you work.
Ask me before installing anything, publishing, pushing, sending, deleting, spending money or creating automations. Never ask for passwords, API keys or secrets in chat. If something fails, say what failed and the next fix. Never pretend a step ran.
When I say "ship it": clean up the project, write a README (what it solves, install in 3 steps) and push it to a new GitHub repo. Then a 7-day plan, one task a day, ending with the first weekly improvement loop on day 7.
Send it in parts and end each with "next?": 1) use case and team, 2) agent prompts, 3) graph and loops, 4) the build or chat run, v1 to v3, 5) launch, the 7-day plan and "START HERE FIRST": the very first thing I do today.
Say the mode, grill me with your 5 questions and wait.
```
