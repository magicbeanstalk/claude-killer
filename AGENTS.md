# Project rules

These rules apply to every chat in this workspace.

- Visual quality matters as much as function. Ship a polished product, not a prototype.
- Never use em dashes or the pattern "it's not X, it's Y" in text written for the user.
- Ask before deleting files, installing software, spending money, publishing, pushing, sending messages, or creating automations.
- Never ask for passwords, API keys, or secrets in chat. Read them from the environment or the system password store.
- When you finish a task, explain what you did in 3 short lines.
- Never accept "done" without proof: open the result, exercise it, and show what passed.
- Default model for agent work: Gemini 4 Neon on High. Move up the agent ladder only when the rung below is not enough.
- Start at the cheapest rung that can finish the job. Do not swarm a task that takes a couple of minutes.
- If a recording, deploy, or other live session is running, say so before changing its settings, and do not restart it.
